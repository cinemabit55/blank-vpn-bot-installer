# Полная инструкция по установке и управлению Blank VPN Bot

Версия инструкции: 8 июня 2026 года.

Эта инструкция рассчитана на человека, который раньше не работал с серверами, доменами, DNS, Docker и Telegram-ботами. Выполняйте действия по порядку и не пропускайте проверки.

В результате на отдельном управляющем сервере будут установлены:

- Telegram-бот без заранее заданного бренда;
- RemnaWave-панель для управления пользователями, подписками и VPN-нодами;
- страница подписки для приложений пользователей;
- веб-кабинет;
- Caddy для HTTPS-сертификатов и доступа по доменам;
- три стартовых тарифа: `Базовый`, `Темные списки`, `Триал`;
- Telegram Stars как единственный включенный способ оплаты;
- команды для добавления нод, платежек и собственных баннеров.

Бот после установки запускается без стандартных баннеров Bedolaga, без выбора языка и без обязательного принятия правил. Основной язык новых пользователей — русский. В коде доступны русский и английский.

## 1. Сначала разберитесь в названиях

В инструкции используются следующие слова:

- **VPS или сервер** — арендованный удаленный компьютер, который работает круглосуточно.
- **Управляющий сервер или control-plane** — VPS, на котором находятся бот, RemnaWave, кабинет и база данных.
- **VPN-нода** — отдельный VPS, через который позже будет идти пользовательский VPN-трафик.
- **IP-адрес** — числовой адрес сервера, например `203.0.113.10`.
- **Домен** — купленное имя, например `example.com`.
- **Поддомен** — дополнительный адрес внутри домена, например `panel.example.com`.
- **DNS** — настройки, связывающие доменное имя с IP-адресом.
- **DNS-only** — DNS возвращает настоящий IP сервера; трафик не проходит через прокси Cloudflare.
- **Proxied** — HTTP/HTTPS-трафик проходит через прокси Cloudflare; в панели это оранжевое облако.
- **SSH** — безопасное подключение к терминалу удаленного сервера.
- **root** — главный пользователь Linux с полными правами.
- **Token, API token, secret key** — секретный ключ доступа. Его нельзя публиковать или отправлять посторонним.
- **Docker container** — изолированно запущенная часть системы, например бот или база данных.

## 2. Что нужно подготовить

До запуска установки подготовьте:

- один отдельный чистый VPS для управляющего сервера;
- один домен;
- Telegram-бота и его token;
- ваш числовой Telegram ID;
- username поддержки или решение использовать только тикеты;
- необязательный публичный Telegram-канал для новостей;
- email для выпуска HTTPS-сертификатов;
- примерно 30–60 минут свободного времени.

Не покупайте VPN-ноды на этом этапе, если хотите сначала проверить только установку бота. Их можно добавить позднее командами `add_direct`, `add_cascade` и другими.

## 3. Покупка управляющего VPS

### 3.1. Где купить

Подойдет любой провайдер VPS, который позволяет установить Ubuntu и выдает отдельный публичный IPv4. Найдите в поиске провайдера по запросу `VPS Ubuntu 24.04`, сравните цену, доступные страны, способы оплаты и отзывы.

Для первого теста выбирайте недорогой сервер. Не покупайте годовой тариф, пока не убедитесь, что провайдер и IP подходят.

### 3.2. Какие характеристики выбрать

Рекомендуемая конфигурация управляющего VPS:

- операционная система: `Ubuntu 24.04 LTS`;
- архитектура: `x86_64` или `amd64`;
- процессор: от 2 vCPU;
- память: от 4 GB RAM;
- диск: от 20 GB SSD;
- отдельный публичный IPv4;
- открытые входящие порты `22/tcp`, `80/tcp`, `443/tcp`, `443/udp`;
- доступ по root-паролю или SSH-ключу.

Не выбирайте:

- сервер с NAT или общим IPv4;
- готовый сервер с установленной панелью, Docker-стеками или VPN;
- сервер, на котором уже находится VPN-нода;
- Windows Server;
- Ubuntu Desktop.

Управляющий сервер должен быть отдельным чистым VPS. Установщик специально остановится, если обнаружит на нем `/opt/remnanode` или `/opt/templar-node`.

### 3.3. Что сохранить после покупки

Провайдер покажет или отправит:

- IP-адрес сервера;
- SSH-пользователя, обычно `root`;
- root-пароль или приватный SSH-ключ;
- иногда нестандартный SSH-порт.

Сохраните эти данные в менеджере паролей. Не отправляйте пароль и приватный ключ другим людям.

Пример подготовленных данных:

```text
IP сервера: 203.0.113.10
SSH пользователь: root
SSH порт: 22
SSH пароль: ваш-секретный-пароль
```

### 3.4. Firewall или Security Group у VPS-провайдера

Некоторые провайдеры имеют отдельный сетевой firewall в личном кабинете. Он работает независимо от Ubuntu.

Если такой раздел есть, разрешите входящие соединения:

```text
22/tcp   SSH
80/tcp   HTTP и выпуск сертификатов
443/tcp  HTTPS
443/udp  HTTP/3
```

Если SSH-порт у провайдера нестандартный, разрешите его вместо `22/tcp`.

Остальные внутренние порты базы данных и RemnaWave открывать в интернете не нужно. Установщик публикует их только на `127.0.0.1` или во внутренней Docker-сети.

## 4. Как зайти на сервер

### 4.1. macOS

Откройте приложение `Терминал`:

- нажмите `Command + Space`;
- напишите `Terminal` или `Терминал`;
- нажмите Enter.

Подключитесь:

```bash
ssh root@203.0.113.10
```

Замените `203.0.113.10` на IP вашего сервера.

При первом входе появится вопрос:

```text
Are you sure you want to continue connecting (yes/no/[fingerprint])?
```

Введите:

```text
yes
```

Затем введите пароль. Во время ввода SSH-пароля символы на экране не появляются — это нормально. Введите пароль вслепую и нажмите Enter.

Если провайдер выдал другой SSH-порт, например `2222`:

```bash
ssh -p 2222 root@203.0.113.10
```

Если провайдер выдал пользователя `ubuntu` вместо `root`:

```bash
ssh ubuntu@203.0.113.10
sudo -i
```

После `sudo -i` приглашение должно начинаться с `root@`. Только после этого запускайте установщик.

### 4.2. Windows 10 или Windows 11

Откройте Windows Terminal или PowerShell:

- откройте меню Пуск;
- напишите `Terminal` или `PowerShell`;
- запустите найденное приложение.

Введите:

```powershell
ssh root@203.0.113.10
```

Windows 10 и Windows 11 обычно уже содержат встроенный OpenSSH-клиент. Если команда `ssh` не найдена, установите компонент `OpenSSH Client` в дополнительных компонентах Windows.

### 4.3. Телефон, планшет или Termius

В Termius создайте новый Host:

- Address: IP сервера;
- Port: `22`, если провайдер не выдал другой;
- Username: `root`;
- Password: root-пароль сервера.

Сохраните Host и нажмите Connect.

### 4.4. Как понять, что вход выполнен

После успешного подключения вы увидите приглашение примерно такого вида:

```text
root@server-name:~#
```

Проверьте систему:

```bash
cat /etc/os-release
```

В выводе должно быть `Ubuntu`, желательно версия `24.04`.

Проверьте IP:

```bash
curl -4 ifconfig.me
```

Он должен совпадать с IP, выданным провайдером.

## 5. Покупка домена

### 5.1. Что именно покупать

Нужен один обычный домен, например:

```text
myvpnservice.com
```

Не нужно отдельно покупать:

```text
panel.myvpnservice.com
sub.myvpnservice.com
cabinet.myvpnservice.com
api.myvpnservice.com
```

Это бесплатные поддомены. Они создаются в DNS после покупки основного домена.

Выбирайте короткий домен латиницей. Для простоты избегайте кириллических доменов и сложных символов.

### 5.2. Вариант A: купить домен в Cloudflare

Этот вариант удобен, если Cloudflare принимает доступный вам способ оплаты:

1. Создайте аккаунт на `https://dash.cloudflare.com/`.
2. Подтвердите email аккаунта.
3. Откройте раздел регистрации доменов.
4. Найдите свободный домен.
5. Проверьте цену регистрации и цену продления.
6. Заполните настоящие контактные данные владельца.
7. Оплатите домен.
8. Подтвердите email владельца домена, если придет письмо.

При покупке через Cloudflare домен сразу использует DNS Cloudflare. Менять nameserver не нужно.

### 5.3. Вариант B: купить домен у любого другого регистратора

Домен можно купить у любого регистратора. После покупки есть два пути:

- оставить DNS у регистратора и выбрать в установщике `manual`;
- подключить домен к Cloudflare и выбрать в установщике `cloudflare`.

Если вы не хотите разбираться с Cloudflare API, используйте ручной DNS у регистратора. Главное, чтобы регистратор позволял создавать A-записи.

### 5.4. Как подключить чужой домен к Cloudflare

Если домен куплен не в Cloudflare, но вы хотите управлять DNS через Cloudflare:

1. Создайте аккаунт Cloudflare.
2. В панели Cloudflare нажмите добавление домена.
3. Введите только корневой домен, например `myvpnservice.com`.
4. Выберите Free plan, если платные функции не нужны.
5. Cloudflare покажет два nameserver, например:

```text
alice.ns.cloudflare.com
bob.ns.cloudflare.com
```

6. Откройте панель регистратора, где куплен домен.
7. Найдите раздел `Nameservers`, `DNS servers`, `NS-серверы` или `Серверы имен`.
8. Замените старые nameserver на два nameserver Cloudflare.
9. Сохраните изменения.
10. Вернитесь в Cloudflare и дождитесь статуса `Active`.

Активация может занять от нескольких минут до суток. Не запускайте установку в режиме Cloudflare, пока зона домена не стала активной.

### 5.5. Что такое четыре поддомена

В этой установке используются:

```text
panel.myvpnservice.com
sub.myvpnservice.com
cabinet.myvpnservice.com
api.myvpnservice.com
```

Назначение:

- `panel` — вход в RemnaWave;
- `sub` — пользовательские ссылки подписки;
- `cabinet` — веб-кабинет;
- `api` — API и webhook Telegram-бота.

Можно выбрать другие слова, но новичку лучше оставить стандартные.

## 6. Настройка DNS

Выберите один из двух способов. Не используйте оба одновременно.

### 6.1. Способ 1: ручной DNS

Этот способ подходит для любого регистратора и не требует Cloudflare API token.

До запуска установки создайте четыре A-записи. Во всех записях укажите один и тот же IP управляющего сервера.

Пример для домена `myvpnservice.com` и IP `203.0.113.10`:

```text
Тип A | Имя panel   | Значение 203.0.113.10
Тип A | Имя sub     | Значение 203.0.113.10
Тип A | Имя cabinet | Значение 203.0.113.10
Тип A | Имя api     | Значение 203.0.113.10
```

В разных панелях поле `Имя` может называться `Name`, `Host`, `Hostname` или `Поддомен`.

Если панель просит полное имя, вводите:

```text
panel.myvpnservice.com
```

Если панель сама добавляет корневой домен, вводите только:

```text
panel
```

TTL оставьте `Auto` или значение по умолчанию.

Если DNS управляется через Cloudflare вручную, для первой установки оставьте серое облако `DNS only` у всех четырех записей. Поддомен `sub` всегда обязан оставаться `DNS only`.

### 6.2. Способ 2: Cloudflare API

Этот способ позволяет установщику самому создать или обновить четыре A-записи.

Предварительные условия:

- домен уже добавлен в ваш аккаунт Cloudflare;
- зона домена имеет статус `Active`;
- вы создали API token с доступом именно к этой зоне.

Создание token:

1. Откройте Cloudflare Dashboard.
2. Откройте `My Profile`.
3. Откройте `API Tokens`.
4. Нажмите `Create Token`.
5. Выберите шаблон `Edit zone DNS` или создайте custom token.
6. Проверьте разрешения:

```text
Zone / DNS / Edit
Zone / Zone / Read
```

7. В `Zone Resources` выберите:

```text
Include / Specific zone / myvpnservice.com
```

8. Нажмите переход к итоговой проверке.
9. Создайте token.
10. Сразу сохраните token в менеджер паролей.

Cloudflare показывает token полностью только после создания. Не используйте `Global API Key`: установщику достаточно ограниченного API token.

При установке рекомендуется ответить `no` на вопрос о проксировании публичных поддоменов. Тогда все записи сначала будут DNS-only. Позже можно включить оранжевое облако для `panel`, `cabinet` и `api`, если все работает.

Никогда не включайте Cloudflare proxy для `sub`. Пользовательские VPN-подписки и специальные заголовки должны приходить напрямую с сервера.

### 6.3. Проверка DNS

На своем компьютере или сервере выполните:

```bash
nslookup panel.myvpnservice.com
nslookup sub.myvpnservice.com
nslookup cabinet.myvpnservice.com
nslookup api.myvpnservice.com
```

Или:

```bash
dig +short panel.myvpnservice.com
dig +short sub.myvpnservice.com
dig +short cabinet.myvpnservice.com
dig +short api.myvpnservice.com
```

При DNS-only должен отображаться IP управляющего сервера.

## 7. Создание Telegram-бота

### 7.1. Создайте бота через BotFather

1. Откройте официальный бот `@BotFather` в Telegram.
2. Убедитесь, что username точно `@BotFather` и у аккаунта есть отметка Telegram.
3. Отправьте команду:

```text
/newbot
```

4. Введите отображаемое имя бота. Его можно будет изменить.
5. Введите username бота. Он обязан заканчиваться на `bot`, например:

```text
my_test_vpn_bot
```

6. BotFather отправит token примерно такого вида:

```text
1234567890:AAExampleSecretToken
```

Сохраните token как пароль. Любой человек с этим token может управлять ботом.

Если token случайно опубликован, откройте BotFather, выберите бота и перевыпустите token.

### 7.2. Как получить username бота

Username — это имя после символа `@`.

Если ссылка бота:

```text
https://t.me/my_test_vpn_bot
```

то в установщик нужно вводить:

```text
my_test_vpn_bot
```

Символ `@` вводить не обязательно: установщик его уберет.

### 7.3. Как получить свой числовой Telegram ID

Telegram ID — это число, а не username.

Самый безопасный способ через созданного бота:

1. Откройте своего нового бота.
2. Нажмите Start или отправьте `/start`.
3. Пока бот еще не установлен, откройте на компьютере терминал.
4. Выполните команду, заменив `BOT_TOKEN`:

```bash
curl "https://api.telegram.org/botBOT_TOKEN/getUpdates"
```

5. Найдите часть:

```json
"from":{"id":123456789
```

Число `123456789` — ваш Telegram ID.

Также существуют сторонние Telegram-боты, показывающие ID, но не передавайте им token своего бота.

Если `getUpdates` возвращает пустой список, еще раз отправьте сообщение своему боту и повторите команду.

Если администраторов несколько, вводите ID через запятую без пробелов:

```text
123456789,987654321
```

### 7.4. Поддержка

Подготовьте username аккаунта поддержки, например:

```text
@myvpn_support
```

Поддержкой может быть ваш личный публичный username или отдельный аккаунт. Если хотите использовать только встроенные тикеты, username все равно можно указать, но выбрать режим `tickets only`.

### 7.5. Новостной канал

Поле новостного канала необязательно.

Если канал уже есть:

1. Сделайте канал публичным.
2. Назначьте ему username.
3. Сохраните username, например:

```text
@myvpn_news
```

Если канала нет, оставьте поле пустым. Позже его можно изменить в конфигурации бота через параметр `NEWS_CHANNEL_USERNAME`.

## 9. Запуск установщика

### 9.1. Перед запуском

Убедитесь, что:

- вы подключены по SSH к управляющему VPS;
- приглашение терминала начинается с `root@`;
- сервер чистый;
- DNS уже создан вручную или Cloudflare-зона активна;
- у вас открыта заметка с подготовленными ответами.

### 9.2. Команда установки

Вставьте команду целиком:

```bash
curl -fsSL https://raw.githubusercontent.com/cinemabit55/blank-vpn-bot-installer/main/scripts/install_blank_vpn_bot.sh \
  -o /tmp/install_blank_vpn_bot.sh
sudo bash /tmp/install_blank_vpn_bot.sh
```

Если вы уже вошли как `root`, `sudo` все равно не мешает.

Не закрывайте терминал во время установки. В зависимости от скорости VPS и загрузки Docker-образов установка обычно занимает 10–30 минут, но на медленном сервере может идти дольше.

Если строка долго не меняется во время скачивания Docker-образов, подождите. Не запускайте установщик второй раз в соседнем окне.

## 10. Как заполнить каждое поле установщика

Ниже поля расположены в том же порядке, в котором их спрашивает установщик.

### 10.1. Install root

Вопрос:

```text
Install root [/opt]:
```

Что это: каталог, куда установятся компоненты.

Что вводить новичку: просто нажмите Enter.

Будут использованы:

```text
/opt/bedolaga
/opt/remnawave
/opt/caddy-remnawave
/opt/cabinet
```

### 10.2. Project display name

Вопрос:

```text
Project display name [VPN Service]:
```

Что это: отображаемое название проекта в кабинете и отдельных интерфейсах.

Пример:

```text
My VPN
```

## 11. Что происходит во время установки

Установщик выводит строки `[status]`. Это не ошибки, а текущий этап.

Основные этапы:

- установка системных пакетов;
- установка Docker и Docker Compose;
- загрузка репозитория;
- проверка чистоты сервера;
- сбор ответов;
- создание DNS через Cloudflare API или вывод ручных записей;
- копирование bundled-кода бота;
- генерация `.env`, Docker Compose и Caddyfile;
- проверка конфигураций;
- запуск RemnaWave и баз данных;
- создание RemnaWave admin и API token;
- запуск бота, кабинета, страницы подписки и Caddy;
- установка команд-алиасов;
- ожидание health check бота;
- вывод итогового summary.

Не пугайтесь строк `Pull complete`, `Download complete`, `Created`, `Started` и `Healthy`. Это нормальный вывод Docker.

## 15. Добавление первой VPN-ноды

Управляющий сервер сам по себе не дает пользователям VPN-подключение. Нужна минимум одна отдельная VPN-нода.

Для ноды купите отдельный чистый VPS:

- Ubuntu 24.04 LTS;
- публичный IPv4;
- root-доступ;
- открытый SSH;
- без уже установленного VPN.

Никогда не используйте управляющий VPS одновременно как ноду.

Посмотреть доступные команды:

```bash
node_commands
```

### 15.1. Прямое подключение

```bash
add_direct
```

Команда создает RU-direct/WARP подключение через один российский сервер без локального сайта-маскировки. Российские домены и IP направляются напрямую с сервера, остальной трафик идет через WARP согласно текущему профилю. Команда спросит IP, пароль, отображаемое название, внутреннее имя и тарифы.

### 15.2. Каскад

```bash
add_cascade
```

Каскад использует два VPS:

- иностранный выход;
- российский вход.

Подготовьте IP и root-пароли обоих серверов.

### 15.3. Дополнительный российский вход

```bash
add_inbound
```

Команда добавляет еще один RU edge к уже существующему иностранному выходу.

### 15.4. Маршруты

```bash
add_routes
```

Команда добавляет домены или IP в правила прямой маршрутизации для выбранного RU edge.

### 15.5. Удаление ноды

Сначала безопасно посмотреть план удаления:

```bash
preview_delete_node
```

Удалить:

```bash
delete_node
```

Читайте план перед подтверждением. Удаление может затронуть RemnaWave, тарифы, DNS, конфиги и удаленный VPS.

### 15.6. Смена SNI

```bash
change_sni
```

Используйте команду, если текущий REALITY target/SNI стал недоступен или блокируется.

## 22. Частые проблемы

### 22.1. Установщик пишет, что APT занят

Пример:

```text
Could not get lock /var/lib/apt/lists/lock
```

Обычно Ubuntu выполняет автоматическое обновление. Текущий bootstrap умеет ждать освобождения APT lock. Не удаляйте lock-файл вручную.

Если процесс действительно завис более чем на 20–30 минут:

```bash
ps aux | grep -E 'apt|dpkg'
```

### 22.2. Установка долго стоит на Docker Pull

Первое скачивание Docker-образов может занять 10–30 минут. Проверьте место:

```bash
df -h
```

И контейнеры:

```bash
docker ps -a
```

### 22.3. Панель или кабинет не открываются

Проверьте:

- A-запись указывает на правильный IP;
- DNS уже распространился;
- порты `80/tcp` и `443/tcp` открыты у провайдера;
- Caddy запущен;
- домен введен без `https://`.

Команды:

```bash
nslookup panel.myvpnservice.com
cd /opt/caddy-remnawave && docker compose ps
cd /opt/caddy-remnawave && docker compose logs --tail=200
```

### 22.4. Страница подписки возвращает 502

Если открывается только:

```text
https://sub.myvpnservice.com/connect
```

без пользовательского short UUID, `502` может быть нормальным.

Проверяйте реальную ссылку пользователя:

```text
https://sub.myvpnservice.com/connect/<user-short-uuid>
```

Также убедитесь, что `sub` — DNS-only.

### 22.5. Бот не отвечает

Проверьте:

```bash
curl -fsS https://api.myvpnservice.com/health
cd /opt/bedolaga
docker compose ps
docker compose logs --tail=200 bot
```

Частые причины:

- неправильный Telegram token;
- token был перевыпущен через BotFather;
- бот уже запущен на другом сервере с тем же token;
- контейнер не может подключиться к базе;
- DNS или HTTPS еще не готовы.

### 22.6. Нет административных кнопок

Проверьте, что в `ADMIN_IDS` указан именно числовой ID вашего Telegram-аккаунта:

```bash
grep '^ADMIN_IDS=' /opt/bedolaga/.env
```

После изменения пересоздайте бота:

```bash
cd /opt/bedolaga
docker compose up -d --force-recreate bot
```

### 22.7. Cloudflare API возвращает ошибку

Проверьте:

- зона домена активна в том же аккаунте;
- token имеет `Zone / DNS / Edit`;
- token имеет `Zone / Zone / Read`;
- token разрешен для нужного домена;
- вы вставили API token, а не Global API Key;
- root domain написан правильно.

Если не удается разобраться, создайте записи вручную и выберите DNS mode `manual`.

### 22.8. Установщик сообщает, что порты 80 или 443 заняты

На чистом сервере до установки они должны быть свободны.

Проверьте:

```bash
ss -lntup | grep -E ':80|:443'
```

Если там уже установлен nginx, Apache, Caddy или другая панель, проще переустановить VPS и начать с чистой Ubuntu.

### 22.9. SSH-соединение оборвалось во время установки

Подключитесь снова:

```bash
ssh root@SERVER_IP
```

Проверьте контейнеры:

```bash
docker ps -a
```

Затем повторно запустите установщик с сохраненными ответами:

```bash
sudo bash /tmp/install_blank_vpn_bot.sh --reuse-answers
```

Для будущих длительных операций можно использовать `tmux`, чтобы процесс продолжался после обрыва SSH.

### 22.10. Ошибка нехватки места

Проверьте:

```bash
df -h
docker system df
```

Для управляющего сервера рекомендуется диск от 20 GB. Не выполняйте `docker system prune --volumes`, если не понимаете последствия: команда может удалить данные.

## 23. Безопасность

Обязательные правила:

- не публикуйте Telegram bot token;
- не публикуйте Cloudflare API token;
- не публикуйте `/opt/blank-vpn-bot-installer/install-summary.txt`;
- не публикуйте `/opt/blank-vpn-bot-installer/answers.last.json`;
- не отправляйте root-пароли и приватные SSH-ключи;
- используйте отдельные пароли для VPS, Cloudflare и RemnaWave;
- включите двухфакторную авторизацию в Telegram, Cloudflare, GitHub и у VPS-провайдера;
- ограничивайте Cloudflare token одной конкретной DNS-зоной;
- сохраняйте секреты в менеджере паролей;
- перед изменением SSH-настроек всегда оставляйте открытой текущую рабочую сессию;
- проверяйте платежи и юридические требования до запуска продаж.

После успешной установки рекомендуется настроить вход по SSH-ключу вместо пароля. Ubuntu рекомендует современные ключи `ed25519`.

Создание ключа на своем компьютере:

```bash
ssh-keygen -t ed25519
```

Копирование публичного ключа:

```bash
ssh-copy-id root@SERVER_IP
```

Проверяйте вход по ключу до отключения парольного входа.
